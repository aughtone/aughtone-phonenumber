# Architecture Decision Records

One hard-to-reverse choice per record: the forces that applied, the option taken, and what was rejected and why. Written when the decision is made rather than afterwards.

**A record is corrected when it is wrong** — a mistaken fact or a rename gets fixed in place. But a decision that is *reversed* outright gets a new record that supersedes it, never an edit; changing direction is itself a decision, with its own forces and rejected options.

Anything that changes a published canonical E.164 form belongs here, because that class of change cannot be undone: consumers have already derived and stored tokens from the old bytes.

**Not here:** how something currently works, or an investigation that has not settled on a choice yet (that is [Research](../research/README.md)). A recommendation only becomes a decision when someone commits to it.
